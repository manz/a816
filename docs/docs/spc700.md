# SPC700

The SNES sound CPU is an SPC700 with its own 64 KB of RAM (ARAM). The
S-CPU uploads a driver into ARAM at boot through the IPL ROM, then
talks to it through four ports. a816 assembles the driver as well as
the game, and links it inside the same build: the 65816 side places
the driver image and reads its symbols, so no second assembler, no
`.incbin` of a stale binary and no hand-copied entry address.

## SPC700 sources

A file named `*.spc.s` (or `*.spc.i` for an include) is SPC700 code;
every other file is assembled for the build's CPU. A build whose entry
file is `*.spc.s` links an ARAM image:

```
$ a816 build driver.spc.s -o driver.bin
```

The image starts at the lowest placed byte and ends at the highest.
`--arch spc700` makes a build SPC700 whatever its file names, and `-f
aram` is the only output an SPC700 build takes (`ips`, `sfc` and `bps`
are for the 65816).

## Operands

Mnemonics and operand order are Sony's: destination first (`mov a,
0x12` loads A). Registers are `a`, `x`, `y`, `ya`, `sp`, `psw` and `c`
(the carry, in bit instructions). An operand that spells one is the
register, so give labels and constants other names.

| Form | Written | Notes |
| --- | --- | --- |
| immediate | `#0x12` | |
| direct page / absolute | `0x12`, `0x1234` | direct page when the value fits a byte |
| forced absolute | `!0x12`, `!label` | always two bytes |
| indexed | `0x12+x`, `!0x1234+y` | |
| register indirect | `(x)`, `(y)`, `(x)+` | `(x)+` increments X |
| indirect | `[0x12+x]`, `[0x12]+y`, `[!0x1234+x]` | the last is `jmp` only |
| memory bit | `0x1234.5`, `/0x1234.5` | 13-bit address; `/` takes the inverted bit |
| direct page bit | `set1 0x12.3`, `bbs 0x12.3, label` | the bit is a number |

The direct page or absolute form is picked from the value. A label not
placed yet or defined in another module has no value at compile time:
write `!` for the absolute form, or define the direct page address as
a constant in a shared include. Otherwise the build stops on
[`E0313`](errors.md). Branches reach -128..127 bytes from the end of
the instruction (`E0315` past that).

The low and high bytes of a word are expressions, as on the 65816:
`#(table & 0xFF)` and `#(table >> 8)`.

## Placement and modules

ARAM is one flat 64 KB bus, so an SPC700 build needs no `.map` or
board: place code with `.alloc NAME at ADDR { ... }` or in a
[pool](freespace-pools.md) over the ARAM range you give the driver.
Modules work as on the 65816: `.import "sound/dsp"` in an SPC700 file
finds `sound/dsp.spc.s` first, then `sound/dsp.s`. Each object records
the CPU it was built for and the linker refuses to link code for two
CPUs into one image.

## Embedding the driver

`.embed "NAME"` inside an `.alloc` of the 65816 build links
`NAME.spc.s` and its imports as their own ARAM program, places the
image there, and defines for the 65816 side, under the last part of
`NAME`:

- `driver.__base`: the ARAM address the image loads at,
- `driver.__size`: the image size in bytes,
- `driver.LABEL`: every label of the program.

The example project `docs/examples/sound-driver/` (built by the test
suite):

```toml
--8<-- "sound-driver/a816.toml"
```

```ca65
--8<-- "sound-driver/src/main.s"
```

`src/sound/driver.spc.s`:

```ca65
--8<-- "sound-driver/src/sound/driver.spc.s"
```

`src/sound/dsp.spc.s`:

```ca65
--8<-- "sound-driver/src/sound/dsp.spc.s"
```

The program builds under the object directory
(`obj/spc700/<name>/`) and is cached like any module: editing a file
of the driver rebuilds the driver, then the module that embeds it.
Symbols flow one way, from the SPC700 program to the 65816 code; an
SPC700 program cannot name a 65816 symbol. `.import` of an SPC700
module from 65816 code fails at link: embed it instead.

## Editor and linter

The [language server](lsp.md) completes and documents SPC700
mnemonics, registers and operand forms in `*.spc.s` files, and
go-to-definition follows `.embed "driver"` to `driver.spc.s` and
`driver.start` to its label. [`a816 check` and `a816 format`](fluff.md)
take SPC700 files; the opcode rules (`OP001`, size inference) are
65816-only.
